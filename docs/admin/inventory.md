# Admin route inventory

Every `/admin` route the kernel registers, each in exactly one group: the group the registry in `crates/kernel/src/routes/admin_nav.rs` places it in, which is the group its sidebar entry, breadcrumb and `<title>` show. The Dashboard row holds the shell's own pages (the Dashboard, your preferences, admin search), which sit above the seven groups.

`the_inventory_lists_every_admin_route_once_in_the_group_the_registry_gives_it` (in `crates/kernel/src/routes/admin_design_tests.rs`) reads the route modules and this table and fails when a route is missing, listed twice, listed in a group the registry does not give it, or no longer exists. Add a route, add its row.

Columns: the path as registered; its methods; its group; the handler and where it is; the template it renders (or what it returns); the gate it checks before anything else. Every gate below is the route's own and is unchanged by B199: the sidebar, landing pages, dashboard and search only show a link, they never admit anyone.

- Dashboard: 8 routes
- Content: 23 routes
- Structure: 44 routes
- Appearance: 3 routes
- People: 17 routes
- Extend: 13 routes
- Configuration: 27 routes
- Reports: 10 routes

## Paths plugins declare

Plugins name admin pages two ways. A `tap_api` route (the plugin serves the page itself through `crates/kernel/src/routes/plugin_api.rs`, gated by the plugin being enabled and then the menu permission) and a `tap_menu` / `tap_admin_nav` entry, which only places a link. The group is the one the registry gives the plugin's declared section: a section naming a group joins it, "System" joins Configuration, anything else joins Extend. "Not routed" means the plugin declares a link to a page no route serves yet; the registry offers it only if the plugin's `tap_admin_nav` declares it, and that check is the plugin's, as it was before.
