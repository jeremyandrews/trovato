## READ THIS FIRST: compile times in this pod
Every `cargo check`/`cargo test`/`cargo clippy` touching crates/kernel takes 15-25 MINUTES
from a touched-source state (single rustc process near 100% CPU the whole time, doesn't
parallelize well despite 8 vCPUs — seems inherent to this crate/pod, not a fluke). Budget
your remaining time accordingly: batch every edit you can before invoking cargo, run builds
with `nohup cmd > /tmp/x.log 2>&1 &` then poll with `sleep N; tail -c 4000 /tmp/x.log` in a
loop (the Bash tool's hard timeout is 600000ms = 10 min, builds exceed that so never block on
one). Always check `ps aux | grep "[r]ustc"` before assuming a build is stuck — if it's near
100% CPU it's just slow, not hung. CRITICAL: never run two cargo invocations that touch the
kernel crate concurrently — they'll block on the target/ directory file lock and waste a full
cycle; if you start a new one, confirm the previous one's process (and children) are actually
dead first (`ps aux`, `kill -9 <pid>` the whole tree if needed) before launching another.
