## What changed this round

Accepted and fixed (see `crates/kernel/src/middleware/edge_cache.rs`,
`crates/kernel/src/services/comment.rs`, `crates/kernel/src/routes/search.rs`,
both `plugins/trovato_cdn_purge_*/src/lib.rs`, `docs/deployment/cdn.md`,
`crates/kernel/tests/edge_cache_test.rs`):

- F1: `request_has_cookie` only read the first `Cookie` header field; now
  reads all of them (`get_all`).
- F2: the default `Surrogate-Key` header joined tags with commas; Fastly and
  Varnish expect whitespace. Separator now follows the header name
  (`tag_separator`): space for `Surrogate-Key`, comma otherwise.
- F3: the 8 KiB overflow fallback only kept `items` if a gather had already
  recorded it; now always inserts `items` in the overflow branch.
- F4: comment writes purged only the commented item's own tag, which the
  overflow fallback (F3) can have already dropped; comment create/update/
  delete now also purge `items`.
- F5: the HTML search route recorded no `items` dependency at all, so an
  empty result had nothing to purge when a matching item later appeared;
  `search_html` now calls `edge_cache::tags::record_items()`.
- F6: `merge_vary_cookie` only read the first `Vary` field, dropping any
  other dimension a handler sent as a separate header line; now merges every
  `Vary` field's values before re-adding `Cookie`.
- F7: a tag header name that collided with `Cache-Control`, `Vary`,
  `Content-Length`, `Content-Type` or `Set-Cookie` silently overwrote it;
  `EdgeCacheConfig::from_lookup` now refuses to start on a reserved name.
- F11: the HTML content-type check was `starts_with("text/html")`,
  case-sensitive, so it matched `text/html-example` and missed
  `Text/HTML`. Replaced with an exact, case-insensitive subtype match
  (`is_html_content_type`).
- F12: a present-but-blank `EDGE_CACHE_TAG_HEADER` silently took the
  default instead of refusing to start; fixed by not treating "present but
  trims to empty" as "absent".
- F13: nothing proved the admin's real "Everything" submission reaches a
  real purge plugin as `all: true` (the existing admin-route test never had
  a plugin loaded, so both scopes passed through the same
  `DrainOutcome::NoPlugin` fallback). Added
  `the_admin_everything_purge_dispatches_all_true_through_a_real_plugin`,
  which installs and enables `trovato_cdn_purge_http` in the `TestApp`'s own
  `AppState` (not a side dispatcher) and asserts the delivered payload.
- F14: the tile create+update delivery test didn't drain between the two
  writes, so the "site" tag after the update could have come from the
  create instead; added an intermediate drain+clear so the final assertion
  is attributable to the update alone. Also extended that same test with a
  comment-purge stage (for F4).
- F15: both purge plugins logged a warning on every job when their
  destination was unset, duplicating a warning the host's
  `variables_get` already logs once per process; removed the plugins' own
  duplicate log calls.

Rejected (reasoning in the final report, `/home/agent/work/report.md`, with
the full finding table): F8 (fixing it needs a host-interface change the
task's own constraints forbid, and the host module's doc comment already
records this as a deliberate, acknowledged tradeoff), F9 (the task's own
"notification" semantics explicitly call for this), F10 (matches an
existing, pre-existing convention elsewhere in the codebase, not a
regression this PR introduced).

  `--workspace --all-features --all-targets`, can exceed the 10 minute foreground
  tool timeout even though `target/` already has a differently-flagged build cached;
  rerun the same command, it resumes from the partial cache and finishes.)
