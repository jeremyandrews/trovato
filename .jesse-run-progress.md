## Notes / gotchas for successor
- Build times are long: cold build of trovato-kernel alone ~7-14 min in this sandbox. Use nohup + background + poll pattern (not foreground with short timeout) to avoid wasted retries.
- `cargo test` test-profile build also compiles the `trovato` bin target (needed for `CARGO_BIN_EXE_trovato` used by the CLI test in user_without_mail_test.rs's `mod cli`), adding more time.
- shared_app() (crates/kernel/tests/common/mod.rs) has NO SMTP configured by default (state.email() is None), so admin "notify new account" / farewell mail always take the "no transport" branch (creates a PasswordResetToken row for logging) regardless of mail_address(). Could not easily integration-test the admin_user.rs/user_delete.rs guard additions this way; relied on code review instead. mail_queue_test.rs builds its own app via `TestApp::with_config` + a loopback SmtpSink for that.
- find_by_mail(''): the anonymous sentinel account (ANONYMOUS_USER_ID, mail='') always exists, so on main `find_by_mail("")` deterministically matches *something* with an empty address (not necessarily the test's own account) — the password-reset regression test checks for ANY password_reset_tokens row created for ANY user with mail='' after a fixed timestamp, not scoped to one user_id, to catch this reliably.
- Self-registration test needs RegistrationMode::Open (shared_app's default registration mode is not Open) and must reuse the cookies from the GET /user/register response for the POST (session-bound CSRF token), same pattern as account_functions_test.rs.
