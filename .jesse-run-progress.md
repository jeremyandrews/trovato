## Design decisions (locked, do not re-derive)

### 404 log
- Migration `crates/kernel/migrations/<ts>_not_found_log.sql`: table `not_found_log`
  (path varchar(2048), language varchar(12), referrer varchar(2048) null,
  hits bigint not null default 1, first_seen bigint not null, last_seen bigint not null,
  PK (path, language), index on hits, index on last_seen).
- `crates/kernel/src/middleware/not_found_log.rs`: new module.
  - `NotFoundHit`, `NotFoundLogSettings` (enabled/retention_days/max_rows/ignore, default
    on/90/10000/the ignore list from the prompt), `SETTINGS_KEY = "not_found_log"`.
  - Shared skip list moved to `crate::middleware::redirect::is_system_path(path)` (used by
    both `check_redirect` and the new layer).
  - `coalesce(&[NotFoundHit]) -> Vec<CoalescedHit>` pure fn, unit tested.
  - `insert_batch` via one `INSERT ... SELECT * FROM UNNEST(...) ON CONFLICT (path,language)
    DO UPDATE` (hits added, last_seen/referrer from newest, first_seen kept via LEAST).
  - `prune(pool, days, max_rows)` : delete by `last_seen < cutoff`, then ctid NOT IN (top N by
    hits).
  - `clear_resolved(pool, redirects_enabled)`: delete rows now covered by a Live url_alias,
    an existing item's `/item/<uuid>`, or (if redirects_enabled) a redirect source.
  - `record_not_found` middleware fn: runs request through `next`, then on final status 404 +
    GET/HEAD + enabled + not system path + not ignored, builds a hit and calls
    `state.not_found_log().record(hit)` (try_send, drops on full channel). Referrer stripped of
    query/fragment, path/referrer truncated to 2048 chars.
- `AppState` gets `not_found_log: NotFoundLogState` field (own mpsc channel + receiver behind
  `tokio::sync::Mutex<Option<Receiver>>` + settings behind `parking_lot::RwLock<Arc<...>>`,
  loaded once at `AppState::new`, like the `languages` field pattern -- NOT like FrontPageConfig's
  TTL/lazy pattern, because the prompt requires zero DB I/O on the request path). Methods:
  `settings()` (sync read), `reload_settings(pool)` (swap after a settings save, also called from
  `clear_local_cache`'s `CacheKind::SiteConfig` branch so other servers pick up a settings change),
  `record(hit)`, `spawn_writer(pool)` (prod, called once from main.rs like system_log), and
  `flush_for_test(pool) -> usize` (drains whatever is queued right now with `try_recv`, writes it,
  for deterministic tests -- tests never call `spawn_writer`).
- Middleware stack position in `main.rs` and in `crates/kernel/tests/common/mod.rs`'s hand-built
  router: insert `record_not_found` layer immediately after the `check_redirect` `.layer()` call
  (i.e. one layer further out, so it wraps check_redirect, both inside `negotiate_language`).
  NOTE: `crates/kernel/tests/common/mod.rs`'s shared router does NOT wire `check_redirect` at all
  today -- existing redirect tests build their own tiny standalone router (see
  `redirect_query_test.rs`). Model `not_found_log_test.rs` the same way: own small router built
  from `shared_app().await.state.clone()`, stacking `negotiate_language` + the new layer (+
  `check_redirect` where relevant) + a 404 fallback, rather than fighting the shared harness.
- Cron (`crates/kernel/src/cron/tasks.rs` + `cron/mod.rs`): new retention fields/setter mirroring
  `system_log_retention`/`set_system_log_retention`, a `cleanup_not_found_log` task (prune) and a
  `clear_resolved_not_found_log` task (the "clearing" pass), both wrapped in `bounded(...)` in the
  `run()` loop like `cleanup_system_log`. `CronTasks` needs a `redirects_enabled: bool` field with
  a setter (`set_redirects_enabled`, mirrors `set_pagefind_enabled`), wired from `state.rs` next to
  `cron.set_pagefind_enabled(enabled_set.contains("trovato_search"))` as
  `cron.set_redirects_enabled(enabled_set.contains("trovato_redirects"))`.
- Clearing on redirect write: `RedirectService::create`/`update` (`services/redirect.rs:547-599`)
  call a new `not_found_log::delete_one(pool, &canonical_source, language)` right after
  `self.invalidate()` (needs the pool, which `RedirectService` already holds as `self.pool`).
- Report route `GET /admin/reports/page-not-found` + settings `GET`/`POST
  /admin/reports/page-not-found/settings` in `crates/kernel/src/routes/admin_reports.rs`, modeled
  on `log_report` (listing/pager) and `save_scheduler_settings` (settings form via
  `crate::form::Form` + `admin_form::check`). Permission: `AnyPermission(&["access site reports",
  "administer site"])` for the report (matches the log report's audience), `administer site` alone
  for settings (matches scheduler settings). Nav entry in `admin_nav.rs` Reports group modeled on
  the "Recent log messages" entry.
- Redirect add form prefill: `add_redirect_form` in `admin_redirect.rs` reads `source`/`language`
  query params (canonicalized via `services::redirect::canonicalize_source`, language checked
  against `state.known_languages()`), inserted into `values` instead of `{}` when present and
  valid; invalid/missing stays exactly as today (empty form).

### Clone
- `ItemService::clone_item(&self, source_id: Uuid, user: &UserContext, with_translations: bool) ->
  Result<Item>`: `load(source_id)` -> 404 if none; `check_access(&source, "view", user)` gate;
  build `CreateItem` copying `item_type`/`fields`/`stage_id`/`language`, title
  `"Copy of {title}"` via `crate::i18n::translate` in the source's language, `author_id =
  user.id`, `status: None` (-> create_moderated computes Draft on a moderated type; prompt says
  "unpublished (Draft on a moderated type)" -- for a non-moderated type force `status: Some(0)` so
  it is unpublished too), `promote`/`sticky: None` (type defaults). Call
  `self.create_moderated(input, None, Some(moderation::DRAFT), user)` (created=None -> now).
  record one extra audit row action `"clone"` with `{"source_id": source_id}` after
  create_moderated's own "create" audit row (create_moderated already audits "create"; add a
  second `self.audit("clone", new_item.id, Some(user), json!({"source_id": source_id})).await`).
  If `with_translations`, query `item_translation` for every row of `source_id` directly (need
  title+fields, `list_translations` only returns (lang,title) -- write own query), and for each
  call `self.save_translation(new_item.id, lang, &format!("Copy of {title}"), &fields, user)`
  (title prefixed via i18n::translate in that translation's own language).
- Permission: route-level check `user_ctx.can(&format!("clone {item_type} content")) ||
  user_ctx.can(crate::content::ADMINISTER_CONTENT)` (is_admin already implied by `.can`), plus
  `allowed(&state, &item, "view", &user_ctx)` for source view access (reuses `check_access`'s
  generic own/any pattern matching for "view").
- Grid: `grid_permissions` in `admin_user.rs` currently has NO per-type "Content types" provider
  at all (confirmed by research) -- add one: loop `state.content_types().list_all()`, push
  `GridPermission { name: format!("clone {} content", ct.machine_name), provider: "Content
  types", description: ... }` per type. `known_permissions` in `config_storage/yaml.rs` needs the
  matching acceptance: add every `clone {type} content` for every registered type into the known
  set the same way (loop content types, same string).
- Routes: `GET,POST /admin/content/{id}/clone` in `admin_content.rs`, built with the
  `crate::form::Form` pipeline (checkbox `with_translations`, shown only when
  `list_translations` is non-empty; submit "Clone"), modeled on
  `manage_search_config`/`save_search_switches`. On success redirect to
  `/admin/content/{new_id}/edit` with a flash message (reuse `CONTENT_FLASH_KEY` pattern).
  Add a `"clone"` key to the `operations` map (~line 87-117) and a Clone link in
  `templates/admin/content-list.html` beside Edit, gated on `ops.clone`.
- No "Edit" link exists on the item's own view page today (confirmed) -- prompt says "a Clone
  link wherever the item page offers Edit to an editor": since there is no such existing link,
  this has nothing to add to (out of scope to invent a new Edit link there). Note this in the PR
  body as a finding, not a gap to silently skip.

### Has-page
- `has_page: Option<String>` field on `ContentTypeFormData` (own, NOT in `DEFAULT_SWITCHES`,
  because that list's `switch()`/`settings()` default every box to `false` when absent, which is
  the opposite polarity). Own `settings()` logic: insert
  `"has_page": self.has_page.is_some()` only... actually need default true when the checkbox
  system always submits the field's presence/absence each save, so once the form round-trips
  through this handler, it is explicit true/false, matching "a missing key reads as on" only for
  types nobody has saved through this form yet. Edit-form GET value population: own
  `unwrap_or(true)` (not the `DEFAULT_SWITCHES` loop's `unwrap_or(false)`).
- `crates/kernel/src/content/type_registry.rs`: do NOT touch `trovato_sdk::types::
  ContentTypeDefinition` (confirmed: it IS the plugin-facing SDK type, no separate kernel-only
  wrapper exists today). Add a second cache map in `ContentTypeRegistryInner`:
  `has_page: Cache<String, bool>`, filled at the same two fill points as `types`
  (`cache_row`/`definition_from_row`'s caller, and `reload_from_db`), reading
  `row.settings.get("has_page").and_then(as_bool).unwrap_or(true)`. Accessor
  `pub fn has_page(&self, type_name: &str) -> bool` (defaults true on cache miss too, i.e. unknown
  type behaves as having a page -- matches "a missing key reads as on").
- `view_item` (`routes/item.rs` ~465+): after loading item+user, if
  `!state.content_types().has_page(&item.item_type) && !user.can(ADMINISTER_CONTENT)` -> same 404
  as item-not-found. If admin, add `context.insert("messages", &[{type: "warning", text: "..."}])`
  -- confirmed no route populates "messages" today, `base.html`'s block is currently dead code, so
  this is the first real producer of it.
- Sitemap (`routes/sitemap.rs`): join `item_type`, filter
  `COALESCE((it.settings->>'has_page')::boolean, true)`.
- Pagefind (`cron/pagefind.rs` ~372): extend the existing `type_rows`/`switches_for` closure
  pattern with a `has_page_for` lookup off the same already-fetched `settings`, filter candidates
  by both.
- New migration redefining `item_search_vector` (latest body in
  `20261128000001_comment_subject.sql:26-113`), copied verbatim into a new migration file plus one
  new guard: fetch `type_settings` once (full `settings`, not just `settings->'search'`), early
  `RETURN ''::tsvector` when `type_settings->>'has_page' = 'false'`, before the existing `include`
  guard.
- Config export/import: `has_page` rides inside `settings` JSON automatically (same as every other
  `DEFAULT_SWITCHES` key) since nothing special gates JSON keys in/out of the type's settings blob
  -- confirm with a round-trip test but expect no separate plumbing needed.
- Out of scope per prompt: Gather/record-reference/embed/API are unchanged (no code there), tests
  must prove it.
