# B312c: operator allowlist for plugin HTTP to private addresses

## State: fixing second-model critic findings (F1-F5), verification in progress

The feature itself (PLUGIN_HTTP_PRIVATE_ALLOW, per-entry clients, docs,
changelog, three internal critic rounds) was completed and verified green in
earlier runs. This run addresses five findings (F1-F5) a second-model review
raised against that diff. Verdicts:

- F1 (redirect to granted hostname on its OWN port still allowed): CONFIRMED.
  Fixed: `entry_redirect_policy` in `crates/kernel/src/host/http.rs` now
  refuses a redirect hop back to the granted hostname on ANY port (previously
  only a different port). Added test
  `redirect_to_the_granted_hostname_on_its_own_port_is_also_refused`.
- F2 (bracketed hostname / unbracketed IPv6 literal silently accepted):
  CONFIRMED. Fixed in `crates/kernel/src/plugin_http_allow.rs`
  `parse_destination_and_port`: brackets now require IPv6 content (literal or
  CIDR); an unbracketed string that parses as IPv6 is refused, must use
  brackets. Added tests: `bracketed_hostname_is_refused`,
  `unbracketed_ipv6_literal_is_refused`, `bracketed_ipv6_cidr_entry_parses`.
- F3 (`999.999.999.999` silently becomes an inert hostname entry): CONFIRMED.
  Fixed: `looks_like_ipv4_literal` in `plugin_http_allow.rs` rejects a
  dotted-quad-shaped destination that failed `IpAddr` parsing, instead of
  falling through to the hostname branch. Added test
  `invalid_numeric_destination_is_refused`.
- F4 (info log fires for configured entries before plugin discovery, so an
  absent plugin gets an "active" line right before the inert warning):
  CONFIRMED. Fixed: `build_plugin_http_allow_runtime` now takes
  `is_known_plugin` and only logs the active-entry line for a known plugin;
  `state.rs` reordered `discover_plugins` before building the allowlist
  runtime so the predicate is available. Added test
  `entry_for_an_unknown_plugin_still_builds_a_working_client` (functional
  check; no tracing-capture infra exists in this suite to assert the log
  line itself was suppressed).
- F5 (DNS-rebinding/redirect refusals in `execute_http_request`/`fetch_stream`
  omit `has_allowlist_entries`): CONFIRMED. Added `has_allowlist_entries: bool`
  parameter to both functions, threaded from `http_allow.has_entries_for(..)`
  at both production call sites (`request`, `open_stream`); all test call
  sites updated (`false` for plain SSRF tests, `allow.has_entries_for("p1")`
  for allowlist tests).
