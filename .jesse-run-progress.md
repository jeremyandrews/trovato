# B300 progress

## Done
- Root cause confirmed: `static/js/ai-admin.js` sent `FormData` (multipart) to
  `test_provider` in `crates/kernel/src/routes/admin_ai_provider.rs`, which only
  accepted `Form<CsrfOnlyForm>` (urlencoded). Axum's rejection bypassed the
  handler's JSON contract, so the script read `data.latency_ms` as undefined.
- Client fix: `static/js/ai-admin.js` now sends
  `new URLSearchParams(new FormData(form))` instead of a raw `FormData` body.
- Latency display hardened: only renders `latency_template` when
  `typeof data.latency_ms === 'number'`.
- Route fix: `test_provider` now takes the whole `Request` and extracts
  `Form::<CsrfOnlyForm>::from_request` by hand, so a rejection (wrong
  content type) returns the same `{success, message, latency_ms}` JSON shape
  as every other failure branch, instead of axum's plain text rejection body.
- Sweep of every `static/js/*.js` using `FormData`/`XMLHttpRequest`:
  - `ai-admin.js` (fixed, was the bug)
  - `trovato.js` line ~105: builds `FormData` only to read values into a plain
    object, then sends `JSON.stringify` with `Content-Type: application/json`
    to `/system/ajax`. Not a mismatch.
  - `file-upload.js`, `admin-media-picker.js`, `media-picker.js`: all send
    `FormData` to `/file/upload`, which takes `Multipart`. Correct, left alone.
  - `block-editor.js`: no direct `FormData` use; editor.js's ImageTool
    uploader posts to `/api/v1/block-editor/upload`, which also takes
    `Multipart` (vendor library behavior, matches the route). Correct.
  - `gather-builder.js`: `XMLHttpRequest` posts JSON (`Content-Type:
    application/json`) to `/api/v1/gather/query`. Not a mismatch.
  - `page-builder-editor.js`: the only `FormData` reference is inside the
    minified React/ReactDOM bundle's built-in form-action handling (`new
    FormData(e)` in `GO`/listener helpers), not a call site hitting our
    routes. Not a mismatch, nothing to fix.
- Regression tests: `crates/kernel/tests/ai_provider_test_connection_test.rs`
  - urlencoded POST to the test route reaches the handler (gets "Provider not
    found." JSON, proving the body was parsed).
  - multipart POST (reproducing the exact old browser body) gets the same
    JSON failure shape, never axum's plain text rejection. Verified this test
    fails (415, no JSON) against the pre-fix handler and passes after the fix
    (confirmed by `git stash` of just the route fix and re-running).
