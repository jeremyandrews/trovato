### New crates/kernel/src/content/moderation.rs shape
```rust
pub const DRAFT/PUBLISHED/ARCHIVED: &str (unchanged ids, kept for builtin + back-compat call sites)
pub const SETTING: &str = "moderation";
pub const WORKFLOW_SETTING: &str = "moderation_workflow"; // item_type settings key naming the workflow id
pub const WORKFLOWS_KEY: &str = "moderation.workflows"; // site config variable key
pub const EDITORIAL: &str = "editorial";
pub const VIEW_LATEST_VERSION: &str = "view latest version";

pub struct State { pub id: String, pub label: String, pub published: bool, pub default_revision: bool }
pub struct Transition { pub id: String, pub label: String, pub from: Vec<String>, pub to: String }
pub struct ModerationWorkflow { pub id: String, pub label: String, pub default_state: String, pub states: Vec<State>, pub transitions: Vec<Transition> }
// All three: Debug, Clone, PartialEq, Eq, Serialize, Deserialize. Field names as written = wire shape.
// Variable value shape: { "workflows": [ ModerationWorkflow, ... ] }

impl ModerationWorkflow {
  fn state(&self, id: &str) -> Option<&State>
  fn label(&self, id: &str) -> String // state.label or "Unknown"
  fn transition(&self, from: &str, to: &str) -> Option<&Transition>
  fn permission(&self, t: &Transition) -> String // format!("use {} transition {}", self.id, t.id)
  fn may(&self, from: &str, to: &str, user: &UserContext) -> bool
  fn targets(&self, from: &str, user: &UserContext) -> Vec<&State> // in self.states order
  fn default_target(&self, from: &str, user: &UserContext) -> Option<String>
  fn state_of(&self, stored: Option<&str>, status: i16) -> String
  fn status_of(&self, state_id: &str) -> i16
  fn is_published(&self, state_id: &str) -> bool
}

pub fn builtin_editorial() -> ModerationWorkflow // today's 3-state workflow, id "editorial",
  // same TRANSITIONS/labels as old static table -> SAME permission names as before.
pub fn is_moderated(settings: &Value) -> bool // unchanged, reads SETTING bool
pub fn workflow_setting(settings: &Value) -> &str // settings.get(WORKFLOW_SETTING).as_str().unwrap_or(EDITORIAL)
pub fn resolve_workflows(value: Option<&Value>) -> Vec<ModerationWorkflow>
  // None or unparsable or empty list -> vec![builtin_editorial()], logged on parse error.
pub fn workflow_by_id<'a>(workflows: &'a [ModerationWorkflow], id: &str) -> Option<&'a ModerationWorkflow>
pub fn problems(value: &Value) -> Vec<String> // validates the moderation.workflows variable itself:
  // parse failure; per workflow: default_state not in states; no published state;
  // state id len>32 or !~ ^[a-z][a-z0-9_]*$; transition from/to naming unknown state;
  // published:true but default_revision:false (invariant from design); same state id with
  // different published/default_revision flags across workflows in the SAME value.
fn fallback_label(id: &str) -> String // title-cases unknown ids for WriteDenied::Display only
  // (Display has no workflow instance available); draft/published/archived map to old labels.
```

### item_service.rs changes
- NEW: `pub async fn moderation_workflow(&self, item_type: &str) -> Option<ModerationWorkflow>`
  one ItemType row read (reuse is_moderated's query path logic): None if not moderated;
  else read WORKFLOWS_KEY variable (SiteConfig::get, no cache, like stage_view), resolve_workflows,
  look up by workflow_setting(settings); if absent, warn! and fall back to builtin_editorial().
- keep `is_moderated()` as-is (still used by moderation_context/list screens quickly without full workflow? -
  actually replace its internal callers with moderation_workflow(...).is_some() where the workflow is
  then needed anyway, to avoid a double query. Keep is_moderated() itself (pure settings check) since
  nothing requires removing it and some simple boolean checks may still want it.)
- `moderation_state_of(item, latest, workflow: &ModerationWorkflow) -> String` (was &'static str, no workflow param)
- `load_for_moderation(&self, item) -> Result<Option<(String, Item, ModerationWorkflow)>>` -- NOTE: adding
  the resolved workflow to the tuple so item_form.rs can label/target without re-querying. Check call
  sites (item_form.rs::moderation_context) when editing - update.
- `gate_transition(workflow: &ModerationWorkflow, user, from: &str, to: &str) -> Result<String, WriteDenied>`
- NEW `WriteDenied::MovedWhileDraft` (or similar) variant: stage move + forward-revision in same save ->
  refused, message "save the stage move separately from a draft over a published item" (exact wording TBD,
  write it in item_service.rs near other Display arms). This is the item-4 bug fix (test 1i).
- create_moderated / update_moderated: use `self.moderation_workflow(&input.item_type).await`, new
  status_target() helper (see below), `forward = !target_state.default_revision && existing.is_published()`
  (was `to == DRAFT`), write forward revision with the ACTUAL target state id (not hardcoded DRAFT).
- status_target(workflow, from, status) -> String: status==1 => first published state (workflow order)
  with transition from `from`, else default_state; status==0 && workflow.is_published(from) => first
  state with !published && default_revision && transition from `from`, else default_state; else default_state.
  (Exact derivation verified against existing content_moderation_test.rs behavior - see transcript, matches.)
- WriteDenied::Transition KEEPS fields `{from: String, to: String}` unchanged (content_moderation_test.rs
  downcast-compares these as raw state id strings "draft"/"published"/"archived" - MUST NOT CHANGE SHAPE).
  Display impl: use fallback_label() (no workflow available in Display).
- Item::list_moderated signature UNCHANGED: (pool, state: Option<&str>, limit) -> Result<Vec<ModeratedItem>>
  (content_moderation_test.rs calls it directly) - but internals change to read moderation.workflows
  variable and bind the array of published state ids (across all workflows in use) to exclude, instead
  of the literal 'published' string. Becomes effectively still fine as free fn on Item (in models/item.rs),
  needs `pool` only, do a SiteConfig::get internally (one extra query, consistent with "resolve on each use").

## IMPORTANT gotchas discovered while coding (do not re-derive)
- Bash tool: must pass `timeout` param (ms) to the tool call itself, not just shell `timeout N`. Default
  is 120s which is too short for first cargo check (~2-8 min depending on cache). Use 590000.
- clippy denies unwrap_used and expect_used in crate source (Cargo.toml lines 218-219), NOT just in test
  files. Had to restructure update_moderated's forward-revision bool+Option<String> pair into a single
  Option<String> (forward_state) to avoid needing .expect() - type-safety instead of runtime assertion.
- `FormElement::select(...).default_value(impl Into<Value>)` - serde_json::Value, String works via Into,
  a borrowed &String does not coerce automatically to the needed impl Into<Value> bound; pass owned String.
- admin_content.rs's new `type_workflows` helper made `pub(super)` so admin_dashboard.rs (sibling module
  under `routes`) can call `super::admin_content::type_workflows(state).await`.
- known_permissions in yaml.rs: when no `moderation.workflows` variable is stored AND none incoming,
  resolve_workflows(None) still returns vec![builtin_editorial()], so a role file granting
  "use editorial transition publish" against a FRESH scratch db (migrated but never imported) still
  validates, because my migration seeds the variable - but even if it somehow didn't, the Rust-level
  fallback covers it too. Belt and suspenders, intentional.
