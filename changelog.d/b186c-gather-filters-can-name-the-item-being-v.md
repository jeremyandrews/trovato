Gather filters can now name the item the page is showing, so one tile placed once serves every item page (B186). Before this, a gather could resolve the current user, the time, the date or a URL argument, but nothing about the item in view, so an "other articles" or "related recipes" tile needed one copy per item. Two new contextual values fill that gap. `"current_item"` is the shown item's id, so `{"field": "id", "operator": "not_equals", "value": "current_item"}` lists every other article. `"current_item.fields.<name>"` (also written `{"current_item_field": "<name>"}`) is one of its fields, so `{"field": "fields.tags", "operator": "has_any_tag", "value": "current_item.fields.tags"}` lists items sharing one of its tags. `has_tag` and `has_tag_or_descendants` take a field holding exactly one tag. The item route hands the item it renders to tile rendering. A gather that names the current item never runs unconstrained: on a page that shows no item, its tile is left off the page; when the item has no value in the named field, the gather returns no rows. A tile's visibility also gained `item_types` (`{"item_types": ["article"]}`), which shows it only on pages showing an item of those types; an empty list is no rule. The tile admin form exposes this as "Content types". Neither tiles nor gather results are cached, so one item's list is never served on another item's page.
